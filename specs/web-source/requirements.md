Governing spec: [spec.md](spec.md).

| `CONN-ARCHIVEBOX-API-WEB-SOURCE-R001` | **Archived pages answer through the web-source contract (rollup).** The archivebox-api connector must implement the web-source contract of `SCION-SOURCE-INGEST-R005.40`. It is the secondary backend and the automatic fallback of `research.web` (`ARBORA-OPS-R067.3`). It composes three archive operations: add a URL, read the snapshot status and read the extracted text. Children `.1` to `.8` deliver it. | See each child. |

They take a `WebFetchRequest` and return a `WebPageResult` or a `WebFetchRefusal`, with `backend=archivebox`. The connector keeps its per-operation ArchiveBox API tools. | `CONN-ARCHIVEBOX-API-WEB-SOURCE-R001.3` | **Snapshot status.** The connector must poll `get_snapshot` (`archivebox_api/api/api_client_core.py:110`) until the snapshot is complete or the request timeout ends. The default poll interval is 2 s. A timeout must refuse with `upstream_failed`. Proving test: `tests/test_web_source.py::test_status_poll_and_timeout`. Caller chain: arbora fleet.call -> web_fetch or web_extract (archivebox_api/mcp_server.py::register_web_tools:340, register_web_source_tools from scion_sdk.ports.web_source) -> archivebox_api/mcp_server.py::get_contract_source:325 -> ArchiveboxSource._snapshot:98 -> archivebox_api/web_source.py::ArchiveWebSource.snapshot:242 -> _wait:228 -> api.get_snapshot (archivebox_api/api/api_client_core.py:110). Shape: ArchiveWebSource._wait loops on get_snapshot until status is in _COMPLETE, sleeping poll_interval_s (default 2.0) and raising WebSourceRefused("upstream_failed") at the timeout_s deadline; clock and sleep are injectable fields. | A complete snapshot returns, and a stalled snapshot refuses with `upstream_failed`. |
| `CONN-ARCHIVEBOX-API-WEB-SOURCE-R001.4` | **Extracted text.** `web_extract` must read the extractor output files of the completed snapshot through a logged-in archive session (`ArchiveSession` in `archivebox_api/web_source.py`), because the archive serves those files only to a session and the REST results carry no text. The session logs in through the admin form with a CSRF token and logs in again when a read is redirected to the login page. It must prefer the main-content extractor output, then the plain-text output. It must return the same metadata fields as the primary backend. `content_digest` is the SHA-256 of the extracted text. Proving test: `tests/test_web_source.py::test_extract_reads_archive_results`. Caller chain: arbora fleet.call -> web_fetch or web_extract (archivebox_api/mcp_server.py::register_web_tools:340, register_web_source_tools from scion_sdk.ports.web_source) -> archivebox_api/mcp_server.py::get_contract_source:325 -> ArchiveboxSource.extract:172 -> ArchiveSession.get_file:140 and get_text:130 (archivebox_api/web_source.py:76) -> login:101 with the admin form. Shape: ArchiveSession (dataclass over a create_http_client httpx.Client) logs in through /admin/login/ with a CSRF token; ArchiveWebSource.extract:253 tries _TEXT_SOURCES in order and builds the metadata dict with content_digest as a sha256 of the text. | The result carries the text, the metadata and the digest of the fixture snapshot. |
