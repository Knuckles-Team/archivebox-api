# CONN-ARCHIVEBOX-API-WEB-SOURCE — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A child row `.n` is one five-minute unit of work. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-ARCHIVEBOX-API-WEB-SOURCE-R001` | **Archived pages answer through the web-source contract (rollup).** The archivebox-api connector must implement the web-source contract of `SDK-SOURCE-INGEST-R005.40`. It is the secondary backend and the automatic fallback of `research.web` (`ARBORA-OPS-R067.3`). It composes three archive operations: add a URL, read the snapshot status and read the extracted text. Children `.1` to `.7` deliver it. | See each child. |
| `CONN-ARCHIVEBOX-API-WEB-SOURCE-R001.1` | **Model.** New `archivebox_api/web_source.py` declares `web_fetch` and `web_extract` with the SDK contract types. It maps a snapshot to `WebPageResult` with `backend=archivebox`. Proving test: `tests/test_web_source.py::test_tool_schemas_match_contract`. | Each tool schema equals the contract schema. |
| `CONN-ARCHIVEBOX-API-WEB-SOURCE-R001.2` | **Add URL.** `web_fetch` must add the URL through `cli_add` (`archivebox_api/api/api_client_cli.py:15`). A URL that already has a snapshot must reuse it and must not add a second snapshot. Proving test: `tests/test_web_source.py::test_add_reuses_existing_snapshot`. | Two calls for one URL leave one snapshot. |
| `CONN-ARCHIVEBOX-API-WEB-SOURCE-R001.3` | **Snapshot status.** The connector must poll `get_snapshot` (`archivebox_api/api/api_client_core.py:110`) until the snapshot is complete or the request timeout ends. The default poll interval is 2 s. A timeout must refuse with `upstream_failed`. Proving test: `tests/test_web_source.py::test_status_poll_and_timeout`. | A complete snapshot returns, and a stalled snapshot refuses with `upstream_failed`. |
| `CONN-ARCHIVEBOX-API-WEB-SOURCE-R001.4` | **Extracted text.** `web_extract` must read the extractor output files of the completed snapshot through a logged-in archive session (`ArchiveSession` in `archivebox_api/web_source.py`), because the archive serves those files only to a session and the REST results carry no text. The session logs in through the admin form with a CSRF token and logs in again when a read is redirected to the login page. It must prefer the main-content extractor output, then the plain-text output. It must return the same metadata fields as the primary backend. `content_digest` is the SHA-256 of the extracted text. Proving test: `tests/test_web_source.py::test_extract_reads_archive_results`. | The result carries the text, the metadata and the digest of the fixture snapshot. |
| `CONN-ARCHIVEBOX-API-WEB-SOURCE-R001.5` | **Refusal and evidence.** Refusals must use the closed reasons of the contract. A snapshot without extracted text must refuse with `extract_empty`. Each result must name `backend=archivebox`, the snapshot ID, the retrieval time and the digest. Proving test: `tests/test_web_source.py::test_refusals_and_provenance`. | Each case returns its reason, and each result names its snapshot. |
| `CONN-ARCHIVEBOX-API-WEB-SOURCE-R001.6` | **Hot-path proof.** The served test binds acceptance to two arbora runs of `ARBORA-OPS-R067.7`. One run uses `backend=archivebox`. The other run forces a primary failure and falls back. Proving test: `tests/test_web_source_served.py::test_archivebox_run_and_forced_fallback`. | Both runs store a Document equal to the primary run, except for `backend=archivebox`. |
| `CONN-ARCHIVEBOX-API-WEB-SOURCE-R001.7` | **Ingest mappings.** The server must serve `manifest://connector` from `archivebox_api/connector_manifest.yml` through the SDK content registration, and the manifest must declare `schema_mappings` for the `Document` and `Chunk` record types mapped to the core classes, so `SourceIngest` resolves `manifest:<connector>#schema_mappings/Document` and `.../Chunk` in the pack the fleet imports (`SDK-SOURCE-INGEST-R004.25`). Proving test: `tests/test_web_source.py::test_served_manifest_maps_document_and_chunk`. | The served manifest maps both record types to the core classes. |
