| `CONN-ARCHIVEBOX-API-CONNECTOR-CONTENT-R003` | **One typed tool per ArchiveBox API operation.** The client (`archivebox_api/api/api_client_{auth,core,cli,crawls}.py`) has one public method per operation of the ArchiveBox 0.9 REST API (`/api/v1/openapi.json`: auth, core snapshots/archive results/tags/any, crawls and crawl files, cli add/update/schedule/search/remove, machine, personas; 46 operations). KG ingest and the web source read 0.9 shapes (`id`, `plugin`, `output_str`; `cli_add(plugins=)`). Caller chain: the archivebox-mcp console script (scion_sdk.cli:serve) -> archivebox_api/__init__.py::connector (Connector(api=Api)) -> scion_sdk.mcp.tool_surface.register_tool_surface -> scion_sdk.mcp.method_tools.register_method_tools over archivebox_api/api_client.py::Api -> one tool per public method. Shape: archivebox_api/api/api_client_base.py::BaseApiClient._send and ._send_form, the mixins api_client_auth.py, api_client_core.py, api_client_cli.py and new api_client_crawls.py composed in archivebox_api/api_client.py::Api; archivebox_api/mcp_server.py keeps only register_kg_tools and register_web_tools. | The set of `(verb, path)` of the client methods equals the upstream operation set, every one is served, and no served tool has an `action` or `params_json` input. Test: `tests/test_surface_contracts.py::test_one_typed_tool_per_upstream_operation`. |
